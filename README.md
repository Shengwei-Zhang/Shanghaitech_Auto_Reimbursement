# 报销助手 · Reimbursement Copilot

上海科技大学 OA 报销的本机助手。npm 包名 `reimbursement-copilot`，GitHub 仓库 `Shanghaitech_Reimbursement_Copilot`（`dev` 开发分支、`deploy` 部署分支，见下文“分支与发布”）。

本项目旨在帮助各位同事更加便捷地制作各种报销单：通过封装真实的 egate 数据接口，减少繁琐、冗余的操作，提高办公效率。

服务固定监听 `127.0.0.1`：默认一人在本机使用，也可以部署在服务器上经 nginx 供多人使用（见下文“多用户部署”）。主路径是**一键报销页面**：后台直接向学校服务器登录（统一身份认证 → 门户 → BPM），再按浏览器操作时实际发出的请求顺序调用 OA 接口，完成**用款申请单**和**境内差旅单**的填写、保存和提交流转，**全程不打开浏览器**；另有**报销单打印**页面，批量打印或下载已提交报销单的打印件。Playwright 浏览器执行器（接口方式的备用路径）、批次草稿和各类查询命令仍然保留；原来的报销管理页面（首页 `/`）已移除，首页直接跳转到一键报销页面。

## 快速开始

需要 Node.js **22+** 和 npm，以及校园网络或学校 VPN。

```bash
npm ci
test -f .env || cp .env.example .env   # 仅首次；已有 .env 时保留
# 在 .env 中设置 OA_LIVE_ENABLED=true 才能真实办单
npm start
```

打开 [报销助手页面](http://127.0.0.1:4317/Reim-Copilot)（开发版地址 `/Reim-Copilot`；GitHub 上的发布版为 `/Reim-Copilot`）。打开 `http://127.0.0.1:4317` 也会跳转到这里。

图片和扫描件的差旅票据需要本机 OCR 模型（约 22 MB，不在仓库中），下载命令见 [境内差旅单](docs/http-travel.md)“本机 OCR”；没有模型时这类附件逐个标为“OCR 不可用”，其余功能不受影响。

已安装依赖时，也可运行 `./scripts/start-local.sh`，或在 macOS 双击 `启动报销助手.command`；脚本依次查找 `OA_NODE_BINARY`、PATH 中的 Node 和本机可用的 Codex Node 运行时，只编译并启动，不安装软件。

## 一键报销（`/Reim-Copilot`，发布版 `/Reim-Copilot`）

页面自上而下：

- **顶栏**：左侧当前位置（如“报销 / 境内差旅单 / 新建”），右侧“报销单打印”、管理员才有的“统计”，以及账号（姓名、工号、时间、退出）。
- **页脚**：每页底部的项目说明和联系邮箱（邮箱取自 `.env` 的 `REIM_CONTACT_EMAIL`，未设置时不显示）。
- **本单概览**：报销类型与单号、所选经费，以及随填写实时变化的关键数字——用款申请单为经费可用、预算项可用、发票、实报金额；境内差旅单为经费可用、差旅合计（含补贴）、携程冲账、应付收款人。余额以 OA 允许本人查看的为准。
- **分区导航**：编号分区（单据与经费、发票、…），随滚动固定在顶部并标出当前分区，点击跳到对应分区。
- **各分区面板**：每个分区一张面板，标题带编号。
- **提交前检查栏**（固定在窗口底部）：已完成项数和逐项状态（经费、发票、收款人、经费明细合计等，完成的标为绿色；没有填写的不算完成，可选的发票单列不计数），右侧为完成方式和提交按钮。这里只是页面上的实时估算，点“提交”时仍做完整核对：有问题时列出每一条，对应的输入框标红，并跳到第一个；点某一条即跳到它的输入框，改动后标红消失。执行时另有 OA 侧的逐步核对。

窗口变窄时自动换行，手机宽度下提交前检查栏不再固定。用款申请单提交后留在本页：任务加入下方“本页提交的任务”列表（状态、当前步骤、停止、详情），表单保留经费、预算项、收款人、用途、报销事由和完成方式，只清空发票和金额，可以马上填写并提交下一单。境内差旅单见 [docs/http-travel.md](docs/http-travel.md)。

同一个人的任务在服务端按提交顺序逐个执行（同一学校登录的请求必须逐个发送，OA 对重叠的请求回“登录超时”）；查询经费、预算项、空单和票夹走另一个只读会话，任务执行期间也能查。多用户部署时，不同用户的任务同时执行、互不等待。一张空单交给某个任务后，不会再交给第二个任务，提交被拒绝时自动退回。执行进度可以“收起”只看最新一步，结束时的提示 5 秒后消失。

1. **登录**：输入学号/工号和密码，由本机后台登录学校。密码只用于这次登录，不保存，也不会返回页面。学校要求图形验证码时（同一账号连续输错密码后会出现），页面显示验证码图片和“换一张”，填写后继续同一次登录；3 分钟内未填写则作废。测试时可在 `.env` 设置 `OA_USERNAME`/`OA_PASSWORD`，页面自动填入学号，密码框留空即用 `.env` 中的密码（多用户部署时不提供）。每次打开页面都重新登录；服务重启后需刷新页面并重新登录。
2. **选单**：下拉框第一项为“新建用款申请单”。登录后先一次取回待办中的用款申请单，再逐张核对，每核对出一张空单就加入下拉框，不必等全部核对完。空单要求“报销单查询”中主表为空，且编辑页没有关联发票、没有经费项目（中途停止的任务会留下主表为空、但已写入内容的单据，这类单据不会列出）。下拉框下方只显示“正在查找空单...”、没有空单或有单据未能核对。
3. **经费**：选择经费类别，再选经费和预算项，列表中显示可用余额（取 OA 的 `showAmount`；经费未授权查看余额时显示“未授权查看”，不读取其他余额字段）。必须先选经费才会读取并显示该经费的预算项；复用模板同样先读经费、选中模板经费，再读预算项并选中，之后才在后台补齐其他经费的余额。任务结束后自动重新读取所选经费的预算项余额。经费和预算项都可以直接输入关键词查找（经费编号、名称、部门，预算项编号、名称、额度；多个关键词用空格分开，须全部包含），用 ↑↓ 选择、回车确定、Esc 取消。
4. **发票**：添加 1–10 张全电发票，两种来源可以混用：
   - 上传 PDF：选择文件、选择文件夹或直接拖入；可多次追加。一个 PDF 含多张发票时按页自动拆成多张，跳过行程单等没有发票号的页。
   - 点“从 OA 票夹选择已上传的发票”，在两个票夹的未报销发票中勾选。默认只列出发票金额等于可报金额的发票，可勾选“显示全部”查看其余；已关联其他单据的不能选。

   每张 PDF 只在本机识别票号、金额、销售方和开票日期，**不查询 OA**，加入后马上可用。发票是否已被报销，在执行时由 OA 的上传接口判断（见下文）。结果列成表格，重复或违规的那张标红，可单独删除或重试，不影响其他发票。

5. **报销限制**：同一销售方（忽略空格和全/半角括号）同一开票日期的发票，在一张报销单内合计不超过 499.99 元；单张发票不限金额。页面当场标红违规发票，建任务时和执行中保存经费之前（按 OA 票夹中的销售方、开票日期和金额）各再核对一次。
6. **其余信息**：实报金额和附件张数自动跟随可用发票的合计与张数，手工改过后不再自动覆盖（清空即恢复）；实报金额少于合计时给出提醒，超过发票合计或可用余额时不能提交。再填写收款人、用途和报销事由。完成方式默认“保存并提交流转”（清空重填后也恢复为此），只想保存时改选“只保存”；提交前的确认框会写明是否自动提交。
7. **收款人（学号 / 工号 / 银行转账户名）**，默认本人工号：
   - 填**学号或工号**（字母数字）：付款方式为“个人银行卡”，提交后按学号/工号在 OA 中查询收款人姓名和卡号。
   - 填**单位户名**（含中文、空格等）：付款方式为“银行汇款”。页面在 OA 供应商库中查找户名完全一致、且有账号和开户行的供应商，列出开户行和账号后四位；只有一个时自动选中，多个时须手动选择，没有时提示先在 OA 中添加供应商。账号取自供应商库，不手工填写。须填写**汇款用途**；**转账金额**等于实报金额（默认发票合计），因为 OA 要求结算金额等于报销金额。银行汇款只走接口方式。
8. **执行**：确认摘要后任务加入下方任务列表，后台在同一登录上依次调用接口，页面每 2 秒刷新进度，正在进行的步骤末尾显示动态的“...”，执行中可随时停止后续操作。
9. **提交按钮旁边**两个按钮：
   - **复用模板**：沿用上一单的经费（含经费类别）、预算项、收款人（银行汇款连同所选账户和汇款用途）、用途和报销事由，只需重新添加发票并确认金额。模板在每次成功启动任务时按工号保存在本机浏览器中；套用时重新查询经费和预算项，已不在列表中的会提示重新选择。
   - **清空重填**：打开全新的空白表单。

后台执行的步骤与核对（`src/automation/http-fill.ts`）：

| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ | -------------------------------------------------------- |

| 票夹核对     | 每个票夹读一次“未报销”列表（最多 100 条）：以前上传过且未关联单据的发票直接复用，不再上传；票夹中选择的发票确认仍可用                                                                                                                       | 否                 | 所选发票已不在票夹、已关联其他单据                       |
| 经费定位     | 按经费编号、预算科目名称各自唯一定位（只读）                                                                                                                                                                                                | 否                 | 不唯一                                                   |

## 境内差旅单

在一键报销页面本单概览的“报销类型”中选“境内差旅单”（清空重填时保留当前类型）。页面按以下顺序排列，用款申请单的预算项、收款人、实报金额等字段随之隐藏：

1. **单据与经费**：新建境内差旅单，或复用报销单查询中本人内容为空的差旅单草稿；选经费后，**经费明细**表在经费下方列出该经费在差旅单下的支出项目（例如“国内差旅/参会费”“会议费”），每行填金额和用途，“＋增加支出项目”加行。第一个金额留空的行**自动填入**差旅合计减去其他行（浅绿色显示；保存时以 OA 算出的差旅合计为准），新加的行须填写金额。各行合计须等于差旅合计（OA 提交时的规则），且不超过各预算项余额。
2. **票据（发票与行程附件）**：这次出差的全部票据都拖到这一处——火车票、机票订单（携程订单页）、住宿发票与水单、会议注册发票、会议通知与日程（PDF、Word、PNG/JPEG），也可从 OA 票夹选择已上传的发票。每个文件只在本机内存中识别，再**自动分类**：
   - **上传票夹**：火车票、住宿发票、会议注册发票、机票行程单和其他全电发票，自动加入下方发票列表，提交时上传到 OA 票夹并关联本单（0–10 张；合计须不少于付款减去补贴，补贴不需要发票）；删除票据时一并移出。
   - **仅解析**：携程机票订单页、酒店水单、会议通知，只用于整理行程，**不保存、不上传 OA**。

   识别后**自动**填入出差人与各段行程（按姓名在 OA 中查到学号/工号），以通知标题作报销事由；选定经费后**自动勾选**订单号相同的携程借款单。金额去向：机票按订单实付金额，住宿费按住宿发票（没有时暂用水单），会务/注册费按会议发票，机票行程单不重复计入，其他发票（如出租车、退票费）计入第一段的“其他”并提示核对。之后再加票据时，出差人与行程只要还没手工改过就重新填入；改过后需点“用票据重新填入出差人与行程”。图片和扫描件用本机 PaddleOCR 识别；铁路电子客票读 PDF 内嵌的全电发票 XML。
3. **出差人与行程**：携程借款单冲账（可输入订单号、摘要或借款人筛选，可多选，按未清余额全额冲账）和情况说明；每位出差人选教工/学生（旁边显示补贴标准：教工 180、学生 100 元/天）、输入姓名在 OA 中查找后选学号/工号（同名时按学号和部门选）；行程逐段填写，实际补贴留空即按标准 × 天数，不得高于标准。**差旅天数**只要求每位出差人各段之和等于行程总天数（首段启程到末段到达，含首尾），可以都填在其中一段。
4. **收款人与附件**：附件张数、报销说明，以及**收款人**表：学号/工号（个人银行卡）或单位户名，紧跟着金额；只有银行汇款才在右侧出现收款账户（OA 供应商）和汇款用途。第一位收款人默认是第一位查到的出差人（手工改过后不再跟随），第一个金额留空的收款人**自动填入**应付金额减去其他人，新增的收款人须填写金额；合计须等于差旅合计减去携程冲账。
5. **完成方式**：默认保存后回读核对并提交流转，也可改选只保存（审批路线用 OA 自动生成的，经费负责人须为所选经费的负责人）。提交后以“报销单查询”状态“提交”且金额等于差旅合计为准。

数字之间的关系以已提交的 D209900000034 核对：差旅合计 5,380 = 经费明细合计；携程冲账 2,250；支付 3,130 = 5,380 − 2,250，按垫付情况分给两位收款人；发票 2,880 少于支付额，差额为补贴。请求链、字段规则和尚未实测的部分见 [境内差旅单](docs/http-travel.md)。

## 报销单打印（`/print-list`）

在一键报销页面右上角点“报销单打印”，新标签页打开，沿用一键报销页面的学校登录（未登录时提示先回一键报销页面登录）。

1. **列出**：向“报销单查询”请求状态为“提交”的最近 100 张报销单（由 OA 按 `queryStatusKind=1` 筛选，含用款申请单、境内差旅单、采购预付及报销单等各类单据），再逐张调用 OA 的打印权限检查，允许打印的才加入列表。审批还停在经费负责人等节点的单，OA 会回复“请等待审批节点到达财务联络人或财务审核岗时进行打印”，不列出。预制、接收、已完成、已中止等状态不查询。
2. **每一行**：
   - **生成打印文件**：在后台向 OA 读取这一张的打印内容并生成 PDF，期间显示“打印文件请求中…”；完成后显示“报销文件已就绪”（不可点击），旁边出现“打印”（直接打开并弹出打印对话框，点过后显示“已点击打印”，仍可再打）和“下载”（保存 PDF，文件名为单号，如 `A209900000029.pdf`）。已就绪的文件 30 分钟内可反复打印、下载，刷新页面后仍保留，退出登录即删除。打印页在独立窗口中打开，打印对话框开着时列表页仍可继续操作。
   - **添加附件**：已占位，暂不可用，待抓取 OA 的添加附件流程后接入。
3. **批量**：勾选多行（可按单号、报销类别、事由、金额或日期筛选，可全选，一次最多 20 张）后点“生成所选打印文件”，每行各自显示进度，同时生成 2 张，已就绪的不再生成；也可用“合并打印所选”“下载所选”把所选报销单合并成一个打印页或一个 PDF，每张单从新的一页开始。

打印内容与 OA“打印”按钮完全相同：报销单主图在前，电子发票每张一页，带页眉页脚和单号水印。请求链与安全处理见 [报销单打印](docs/http-print.md)。

## 多用户部署

`.env` 中设置 `REIM_DEPLOYMENT=server` 和 `REIM_PUBLIC_ORIGIN=https://你的域名` 后，服务经同一台机器上的 nginx 供多人使用：每个浏览器有自己的会话、CSRF 令牌和学校登录（一人登录或退出不影响他人），用款申请单任务只属于创建它的浏览器，不同用户同时执行，同一用户逐个执行；只接受所配置的 https 地址，Cookie 带 `Secure`，`.env` 中的账号密码不提供。默认的本机模式行为不变。配置、nginx 示例和注意事项见 [多用户部署](docs/deployment.md)。

**使用统计**：`REIM_ADMIN_ACCOUNTS` 中的账号登录后，右上角出现“统计”，打开 `/admin`：在线人数、正在执行与排队的任务、服务过的用户数、处理与成功的报销单（按类型分列已提交、已保存、待核对、失败、已停止）、登录与验证码次数、最近 30 天逐日数据。其他账号看不到入口，统计接口对他们返回 404。统计保存在 `<OA_DATA_DIR>/stats`，用户以账号加随机密钥的摘要计数，不保存工号、姓名、单据号或金额。

## 安全约束

- 只在学校三个 OA 主机之间请求与跳转；Cookie 只接受 `shanghaitech.edu.cn` 及其子域。
- 不打印、不保存密码、Cookie、ticket 或 csrfToken；学校会话只保存在本机服务的内存中，重启服务即失效。
- 同一 BPM 会话的请求串行发送（并发会被 OA 判为登录超时）。登录后另用同一次学校登录（CAS）开第二个 BPM 会话，专门处理页面上的只读查询（经费、预算项、空单、票夹、报销单打印），各自排队：任务执行期间仍可查询经费和预算项、复用模板。唯一的并发例外是发票上传和票夹查询，与 OA 页面本身的做法相同。
- 每个写请求只发一次；回执不符即停止。最终提交请求最多发送一次，结果不明时只读查询状态，绝不自动重试。
- 收款人查询所需的加密只读取弹窗脚本中的字面量参数，不执行学校下发的脚本；结构变化时停止。
- 差旅票据只在本机内存中解析，不写入磁盘、不发给 OA 或任何外部服务（属于发票的那些按用户的选择上传到 OA 票夹）；OCR 在本机运行（onnxruntime-node），图片不离开本机。
- 打印页只保留 OA 打印页面中的样式和内联图片，去掉脚本、事件属性和外部链接，并以严格的 CSP 提供；合并打印的链接只能打开一次、10 分钟内有效，生成的打印文件只在内存中保留 30 分钟。生成 PDF 时禁用脚本并拒绝所有网络请求。
- 多用户部署时，每个浏览器的学校登录、任务和打印文件互不可见；会话空闲 120 分钟后连同学校登录一起结束。

测试使用合成发票和模拟的 OA 接口，不进行真实报销。**请求基准**（`tests/golden.cjs`、`tests/fixtures/golden/`）把两种报销单的六条典型请求链发给 OA 的每个请求逐字段固定下来，改代码时任何一个字段变化都会让测试失败并指出是第几个请求；有意改变请求时用 `UPDATE_GOLDEN=1 npm test` 重新记录并审阅差异。GitHub 每次推送都运行全部测试（`.github/workflows/test.yml`）。`tests/easy-page.spec.ts` 在真实浏览器中打开页面，所有 `/api` 请求由测试应答，核对页面最终发出的请求体。新增或调整 OA 请求时，先用浏览器执行器配合 `OA_NETWORK_CAPTURE=true` 抓取实际请求，再按抓包补充模拟接口和测试；学校接口的回复可能变化（例如 2026-10-15 提交成功的回复由空响应变为 `{"data":"ok","status":1}`），以实网结果为准。

## 分支与发布

| 分支     | 作用                                                            | 更新方式                                           |
| -------- | --------------------------------------------------------------- | -------------------------------------------------- |
| `dev`    | 开发分支                                                        | 每次同步一个提交                                   |
| `deploy` | 部署分支，部署时使用                                            | 发布时快进到 `dev`：部署的内容一定先同步到过 `dev` |
| `main`   | GitHub 默认分支（不加 `-b` 克隆时得到的），始终与 `deploy` 相同 | 随 `deploy` 一起更新                               |

GitHub 上的代码是**脱敏后的发布副本**：测试夹具和文档中的真实姓名、工号、报销单号、携程订单号、经费与部门编号都已换成同格式的占位值，提交作者为 `Reimbursement Copilot`，不含开发历史。每次同步前先检查是否残留个人信息（手机号、身份证号、邮箱、真实格式的单号等），并在脱敏副本中运行全部测试，任一不通过即不发布。含真实信息的完整开发历史只保存在本机开发仓库，不推送到 GitHub。

页面地址随所在分支而定：`deploy`、`main` 分支为 `/Reim-Copilot`，其他分支（`dev`）为 `/Reim-Copilot`，在服务启动时读取当前分支（切换分支后重新 `npm start`）；GitHub 上的发布副本一律为 `/Reim-Copilot`。`/` 会跳转到当前地址。

部署时克隆 `deploy`：

```bash
git clone -b deploy <仓库地址> reimbursement-copilot
cd reimbursement-copilot && npm ci && cp .env.example .env   # 在 .env 中设置 OA_LIVE_ENABLED=true 才能真实办单
npm start
```
